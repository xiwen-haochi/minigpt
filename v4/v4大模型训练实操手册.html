第 1 步训练 Byte-Level BPE 分词器

为什么中文不需要 jieba？现代大模型统一使用 Byte-Level BPE：先把文本转成 UTF-8 字节序列（任何语言都变成 0-255 的字节），再在字节上反复合并最高频的相邻片段。中文字符会被自动学成「子词」，既不需要预分词，也永远不会遇到未登录词（OOV）——任何生僻字最坏情况就是退化成 3 个字节。

  • 词表 32000：小模型够用，且能用 uint16 存储 token 流（省 4 倍磁盘）。
  • 3 个特殊 token：<|endoftext|>（文档边界）、<|im_start|> / <|im_end|>（对话标记），固定占词表最前。
  • 分词器要在「小说 + 对话」混合语料上训练，覆盖面才够。
01_train_tokenizer.py

第 2 步数据加工：文本 → 二进制 token 文件

预训练数据：小说按段落攒成约 1000 字的块，打乱后 99% 训练 / 1% 验证，编码成一条超长 token 流（文档间插 <|endoftext|>），用 uint16 落盘。训练时随机切片，磁盘上几个 G 的语料也能用 memmap 零拷贝读取。

SFT 数据：每条对话套上 ChatML 模板，编码后填充到定长 768。关键点：system 人设 + 问题部分的 label 置为 -100，loss 只计算回答部分——这样模型只学「怎么答」，不学「怎么问」。结尾强制带 <|im_end|>，模型才学会停下来。

关于本项目的语料：data/sft_raw.jsonl 是 ShareGPT 格式，每条对话都带一段约 300 字的 system 人设（欢乐幽默的聊天伙伴「颜柳」）。人设也会被编进模板参与训练（但不产生 loss），所以 MAX_SFT_LEN 设为 768——如果用 512，回答末尾的 <|im_end|> 会被截掉，模型将永远学不会停止。
02_prepare_data.py

第 3 步模型定义（被训练/聊天脚本共用）

这是 v4 的核心文件，Llama 风格 Decoder-only Transformer，三个训练脚本都会 import 它：

  • RMSNorm：LayerNorm 的简化版，省掉减均值，更快更稳；在 fp32 下算均方根防止半精度下溢。
  • RoPE：不给 token 加位置向量，而是按位置「旋转」q/k 的每对维度，相对位置信息天然编码进注意力，长度外推性好。
  • SwiGLU：两路投影相乘（门控）再投影回来，比普通 GELU-MLP 表达力强。
  • SDPA：F.scaled_dot_product_attention 自动选择最优注意力内核，三平台通用。
  • pick_device()：一处判断 cuda(bf16/fp16)/mps/cpu，所有脚本复用。
model.py

第 4 步预训练：在小说上学语言

预训练任务就一个：给前 t 个 token，预测第 t+1 个。海量重复这个「接龙」游戏，模型就学会了语法、常识和叙事。工程要点：

  • 混合精度：老 CUDA 卡不支持 bf16，自动用 fp16 + GradScaler（先放大 loss 防梯度下溢，更新前再缩回来）。
  • 梯度累积：显存放不下大 batch，就分 4 次小 batch 累计梯度再更新一次，等效 batch 64。
  • 学习率：前 200 步线性升到 3e-4，再余弦退火到 3e-5，避免初期炸、后期细调。
  • 断点续训：检测到 checkpoints/pretrain_last.pt 就自动接着练，想从头练就删掉它。
  • 验证集 loss 创新低才更新 pretrain_best.pt。
03_pretrain.py
显存不够？把 BATCH_SIZE 调成 8 或 4，同时把 GRAD_ACCUM 调成 8 或 16，等效 batch 不变。12 层 768 维约 1.1 亿参数，fp16 训练大约占 4-6GB 显存。

第 5 步SFT：在单轮对话上学接话

预训练模型只会「续写」，不会「对话」。SFT 用套好模板的问答数据继续训练，两个关键改动：

  • loss 掩码：ignore_index=-100，问题部分不产生梯度，模型只学回答。
  • 更小学习率：1e-4（预训练的 1/3），在已有能力上微调，避免「学新忘旧」（灾难性遗忘）。

常见问题

  • CUDA out of memory → 调小 BATCH_SIZE，同比例调大 GRAD_ACCUM。
  • loss 不降 → 检查 token_stream/*.bin 是否生成成功；学习率降到 1e-4 试试。
  • SFT 后不会停 → 说明对话数据里 <|im_end|> 的监督被截断了，检查 MAX_SFT_LEN 是否太小。
  • 回答像小说不像对话 → SFT 轮数不够或对话数据太少；也可以把 SFT 的 EPOCHS 加大到 5。
  • MPS 上比 CPU 还慢 → 小模型在 MPS 上收益有限，属正常现象；认真训练请用 CUDA 机器。

继续进阶的方向

  • GQA（分组查询注意力）：KV 头数少于 Q 头数，推理省显存。
  • 更多数据 + 更大模型 + 更长训练，是提升效果最确定的路径（Scaling Law）。
  • SFT 之后还可以接 DPO/RLHF 做偏好对齐。
