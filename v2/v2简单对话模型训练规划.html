0.01B · 蒸馏流水线 · 只讲流程与原理

第二代小智
作战手册

目标：1000 万参数、能进行数轮自然对话。路线：让本地 Gemma 当老师，蒸馏出几万条对话当教材；分词器升级为 BPE，取数升级为标准 DataLoader，训练升级为带验证集监控的正经流程。每一步只讲"做什么、为什么"。

参数 ×12（86万 → 1000万） 语料 ×100+（221条 → 数万条） 字符级 → BPE 手工 batch → 标准流水线

全景 · 八个阶段一条河

上游是数据和分词器，中游是模型和训练，下游是评估和迭代

00

能力定标 · 写下成功标准

作用：防止训练完不知道算不算成功

动手前先写一张"验收考卷"：30~50 个测试问题 + 每题的合格标准。训练是长跑，这张考卷是你全程唯一的锚。

建议的合格线：连续 3 轮对话不跑题、不复读；人设回答 10 次里 8 次一致；对话格式错误率 < 2%。没见过的话题能礼貌地"打太极"也算合格——对 0.01B 来说，得体的"不知道"是核心竞争力。

为什么知识问答不行：1000 万参数连一部《新华字典》的"知识量"都装不满，它学的是"对话的形状"，不是事实。所有事实性内容都应该靠蒸馏数据里"以查证为准"式的安全回答兜底。

01

蒸馏 · Gemma 写教材

作用：小模型吃不下互联网，只能吃"定制教材"

核心思想：1000 万参数学不了万亿 token，但可以学会"某一类对话的分布"。让 Gemma 针对你的目标批量生成 2~5 万条高质量对话——它相当于把大模型里与你目标相关的行为，"压缩抄写"给小模型。

三种生成模式要混着用：① 给种子问题，Gemma 生成回答（覆盖知识型套路）；② 让 Gemma 一次写 10 个同主题不同问法（问法多样性）；③ 给开头两句，让它续写完整 3~6 轮多轮对话（多轮能力的关键来源）。

多样性三板斧：话题维度（日常/情绪/爱好/求助…至少 30 类）× 风格维度（正式/俏皮/简短/详细）× 人设维度（学生/上班族/好奇宝宝）。三维交叉抽样去调 Gemma，避免数据全是"一种腔调"。

生成参数：温度 0.8~1.0 偏高一些换取多样性；每条数据人工抽检 5%，发现跑偏立刻改提示词。另外务必蒸馏一批"拒答/转移话题"样本（约 5~10%）——它们是小智面对不会的问题时的安全网。

02

清洗与格式化 · 教材编辑室

作用：决定模型上限的往往是数据，不是模型

Gemma 的产出不能直接用：采样撞车、截断残句、格式漂移都需要清洗。这步的黄金法则是顺序不能乱——先去重再过滤再模板化，最后切分验证集，任何颠倒都会造成验证集泄漏，训练指标好看但实际变差。

聊天模板是本项目最重要的决定之一：定义统一的特殊标记（如 user / assistant 两类标记 + 对话结束符），多轮对话序列化成一条"带标记的长文本"。最关键的纪律：训练时用什么模板，推理时就要一字不差地用什么模板——90% 的"模型胡言乱语"其实是模板不一致。

规模建议：2~5 万条对话、其中多轮对话占一半以上，总量约 3000 万~1 亿字符。这个量对 0.01B 是"吃得下又吃不腻"的区间。别忘了把你一代小智的身份问答（10 种自我介绍）也格式化后混进去——人设要靠它传承。

03

BPE 分词器 · 换正规军

作用：小模型升级的最大单项杠杆

用 HF tokenizers 库在你自己的蒸馏语料上训练一个 BPE 分词器（这就是"用现在常用的"做法——所有现代模型都是先在语料上练分词器，再练模型）。注意不要直接用 GPT-2 的旧分词器：它对中文几乎不合并，一个汉字拆 3 个字节，太浪费。

关键参数：词表 8000~16000；务必预留特殊标记（聊天模板的 user/assistant/结束符等）。训练完做一次压缩率体检：用分词器编码验证集，中文应达到约 1~1.5 token/字。压缩率太差就调词表大小重训。

为什么词表不能太大：词表直接吃参数预算——嵌入层 = 词表 × 维度。8192 词表 × 256 维 = 约 200 万参数，已经占掉总预算的两成。小模型配小词表，是有意的取舍。

04

模型配置 · 把预算花在刀刃上

作用：0.01B 的每个参数都要精打细算

参考配置：词表 8192 · 维度 256 · 层数 8 · 注意力头 8 · 上下文 512。三个设计决定背后的理由：层数多而维度适中，深网络比宽网络更会"讲条理"；上下文 512 个 BPE token 约等于 350~500 个汉字，够 6~8 轮对话；嵌入层权重共享，省下的参数让给更多层数。

自检公式：写完配置先算一遍总参数，落在 9M~12M 都算达标。注意按 0.01B 标准算的是非嵌入参数约 7M 也有另一种口径——两种算法都行，但自己要统一口径，训练前后对比才有意义。

RoPE 位置编码 + RMSNorm + SwiGLU 是当代标配，直接照抄现代开源小模型（如 Qwen 系列小尺寸版）的配置表最稳——你是在"复刻一条被验证过的路线"，不需要发明新东西。

05

训练 · 上标准流水线

作用：让每一份算力都花在新知识上

一代的手工 get_batch 有两个隐患：语料重复采样浪费、无验证集监控。二代的标准做法：全语料预分词并拼接打包成一条长 token 流，DataLoader 负责随机切片组批——这是 nanoGPT 到所有大厂都在用的"打包流"方案。

超参数起点：批次 32~64 × 序列 512；学习率 3e-4~6e-4（比一代的 3e-3 低一个量级——模型大了、数据多了，大学习率会震荡）；预热几百步 + 余弦退火；训练 2~3 个 epoch。

时间预估（M1 · 16G · MPS）：0.01B 前后向大约每秒几十万 token，按 5000 万 token × 3 epoch 算，粗估 3~8 小时。建议睡前挂机；每 30 分钟存一次断点，训练中断可续。

MPS 提醒：混合精度在 Apple GPU 上支持不完整，浮点 32 稳妥但慢约一倍；可以先小步数试跑标定速度，再决定精度方案。loss 落到 2.0~2.8 区间且验证集不再下降，就是合理的停机点。

06

评估调错 · 当一次医生

作用：把"感觉不太行"变成可执行的修复项

用阶段 00 的 50 题考卷逐题打分，把失败案例归类——大部分故障都能映射到"数据、模板、采样"三个源头之一。左图是四种最常见病症的速查表。

一个重要的心态：0.01B 的评估没有自动分数可看（BLEU 之类与对话体验几乎不相关），你自己的耳朵就是唯一可靠的指标。建议每次评估都录音式记录：题目、回答、你的 1~10 分、归因。这些记录就是下一轮迭代的路标。

分辨率参考：50 题里 ≥40 题达标、且复读和格式错误基本消失，就可以进入部署；否则按归因回到阶段 01/02 补数据，回到 05 重训——注意是"回到数据"而不是"继续训练"，数据是因，能力是果。

07

迭代与部署 · 让飞轮转起来

作用：好模型不是一次训出来的，是循环出来的

部署用你上一页学过的铁路：mini_hf → GGUF / MLX 一行转换。真正的增量价值在部署之后——真实使用中遇到的坏例，是全世界最珍贵的训练数据，因为它们正好是你的模型"最缺的那一块"。

飞轮的节奏：每轮迭代只修"出现频率最高的一类问题"（比如这轮只治复读），改动控制在数据与采样层面；架构和超参确定后就冻结，避免每次都推翻重来。

进阶里程碑（按序解锁）：① SFT 后接一轮 DPO/RLHF 式偏好微调；② 字节级 → 更大词表 + 更长上下文；③ 参数爬到 0.05B~0.1B（16G 训练的舒适区上限）。每一步的流程都和本页完全相同——变的只是数字。
