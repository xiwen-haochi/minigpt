BPE 分词器手册

字符级分词像一个字一个字啃书的小学生，又慢又累。BPE 把高频字词合并成"词块"，一句话的 token 数直接砍到三分之一——同样的上下文窗口装三倍内容，训练还更快。这份手册带你在自己的教材上，练一个专属小智的分词器。

00

为什么换 · 最大单项杠杆

作用：同样的教材，更薄的厚度

字符级分词把"今天"拆成两个字，模型要花两步才能"读完"。BPE 的做法很朴素：统计语料里哪些组合出现得最频繁，就把它们合并成一个词块——"今天""我们""小智"各占一个 token。

为什么必须在自己的语料上练？词块是从数据里统计出来的：闲聊教材里高频的是"心情""周末""睡不着"，法律教材里高频的是"依据""条款"。直接用别人的分词器，等于穿别人的鞋跑步。所有现代模型都是先练分词器、再练模型，我们照做。

词表不是越大越好：嵌入层参数 = 词表 × 维度。8192 词表 × 256 维 ≈ 200 万参数，已占掉 0.01B 预算的两成。小模型配小词表，是有意的取舍。

01

训练原理 · 统计与合并

作用：懂原理才知道体检在看什么

BPE 训练就是循环两件事：数频率（语料里哪对相邻单位最常一起出现）和合并（把它变成一个新词块）。循环几千次，词表从几百个字符长成 8192 个词块。

两个工程细节：① 我们启用字节级回退——任何生僻字、emoji、乱码都能拆成字节兜底，永远不会出现"未知符"；② 三个聊天模板标记注册为特殊标记，它们永远整体占一个 token，不会被拆碎——这是对话格式稳定的根基。

实现用的是 HuggingFace 的 tokenizers 库（Rust 内核，几千条语料秒级练完）。你不需要懂它的内部，只需要看懂下一节的体检报告。

02

三道体检 · 及格线画在这

作用：把"感觉能用"变成"指标合格"

分词器的质量不看感觉，看三个硬指标：压缩率（决定上下文利用率）、特殊标记完整性（决定对话格式）、往返一致性（决定编解码可靠）。脚本练完自动全部检查并打分。

压缩率为什么用验证集考？在训练集上考会"作弊"——词块本来就是从这些句子里统计出来的。验证集是分词器没见过的文本，它上面的压缩率才代表真实世界的表现。

不合格怎么办：压缩率高于 1.5 → 词表太小，调大 VOCAB_SIZE 重练；低于 1.0 → 多半是特殊标记和短句拉低了均值，若长句压缩率正常就不用管。体检的本质是给你一个"要不要重练"的决策依据。

03

跑起来 · 一分钟出词表

作用：供料、训练、保存、体检全自动

把脚本存为 train_tokenizer.py，和 train.jsonl / val.jsonl 同目录，装一个 tokenizers 库就能跑。产出只有一个文件：tokenizer/tokenizer.json——训练脚本和推理脚本将来都加载它。

唯一要盯的参数是 VOCAB_SIZE：8192 是"嵌入层参数"与"压缩率"的平衡点。教材还只有几百条时词表可能练不满（会有警告），这很正常——等数据涨到几万条，重跑一次即可，词表会随教材一起长大。

纪律重申：分词器只用 train.jsonl 练，val.jsonl 只用来体检。这个分工和模型训练时"训练集学习、验证集监考"是同一条纪律。

完整可运行脚本 · train_tokenizer.py

复制 → 与 train.jsonl 同目录保存 → conda activate f10 && pip install tokenizers && python train_tokenizer.py 

# -*- coding: utf-8 -*-
"""
train_tokenizer.py —— 小智二代 · BPE 分词器训练脚本
作用：在清洗后的 train.jsonl 上训练专属 BPE 分词器，并做三道体检
用法：pip install tokenizers && python train_tokenizer.py
依赖：仅需第三方库 tokenizers（HuggingFace 出品，Rust 内核，秒级训练）
"""

import json      # 读取 jsonl 教材
from pathlib import Path  # 跨平台路径处理（macOS / Linux 通用）

from tokenizers import Tokenizer, models, trainers, pre_tokenizers, decoders

# ==================== 可调参数区（只改这里） ====================
TRAIN_FILE = Path("train.jsonl")  # 分词器只用它练（防验证集泄漏）
VAL_FILE = Path("val.jsonl")      # 体检考场：衡量压缩率的真实水平
OUT_DIR = Path("tokenizer")       # 输出目录：tokenizer.json 存在这里
VOCAB_SIZE = 8192   # 词表大小：小模型配小词表，嵌入层才不吃爆参数预算

# 特殊标记：必须与清洗脚本 clean_split.py 里的聊天模板一字不差！
SPECIAL_TOKENS = ["<|user|>", "<|assistant|>", "<|end|>"]

# 压缩率健康区间：中文教材约 1.0~1.5 token/字
GOOD_RATIO_MIN, GOOD_RATIO_MAX = 1.0, 1.5


# ==================== 四个类，一个类只做一件事 ====================
class CorpusExtractor:
    """职责：只负责供料——从 jsonl 里把 text 字段逐条抽出来"""

    def __init__(self, path):
        """path：教材文件路径（Path 对象）"""
        self.path = path

    def all_texts(self):
        """读取全部 text 字段；返回字符串列表，坏行跳过"""
        if not self.path.exists():
            raise SystemExit(f"[stop] 找不到 {self.path}（请先运行 clean_split.py）")
        texts = []
        for line in self.path.read_text(encoding="utf-8").splitlines():
            try:
                texts.append(json.loads(line)["text"])
            except (json.JSONDecodeError, KeyError):
                continue  # 坏行跳过，不干扰训练
        return texts


class BpeTrainer:
    """职责：只负责训练——在你的语料上练一个专属 BPE 分词器并保存"""

    def train(self, texts):
        """
        参数：texts 训练文本列表
        返回：(训练好的 Tokenizer 对象, 保存路径)
        """
        # BPE 模型 + 字节级回退：生僻字/emoji 都能拆成字节兜底，永无未知符
        tokenizer = Tokenizer(models.BPE())
        tokenizer.pre_tokenizer = pre_tokenizers.ByteLevel(add_prefix_space=False)
        tokenizer.decoder = decoders.ByteLevel()  # 保证"编码再解码 = 原文"
        trainer = trainers.BpeTrainer(
            vocab_size=VOCAB_SIZE,
            special_tokens=SPECIAL_TOKENS,  # 特殊标记永远占据词表前几个坑位
            # 关键：把 256 个字节全部纳入初始字母表，否则语料里没出现过的字节
            # 在编码时会被静默丢弃（"是谁？"可能只剩半个字）——这是最易踩的坑
            initial_alphabet=pre_tokenizers.ByteLevel.alphabet(),
            show_progress=True,
        )
        tokenizer.train_from_iterator(texts, trainer)
        OUT_DIR.mkdir(exist_ok=True)
        out_path = OUT_DIR / "tokenizer.json"
        tokenizer.save(str(out_path))
        return tokenizer, out_path


class CompressionChecker:
    """职责：只负责体检——压缩率、特殊标记、往返一致，三道关卡"""

    def __init__(self, tokenizer):
        """tokenizer：刚训练好的 Tokenizer 对象"""
        self.tok = tokenizer

    def check(self, val_texts):
        """
        在验证集上执行三道体检；返回报告 dict：
        ratio 压缩率 / special_ok 特殊标记完整性 / roundtrip_ok 往返一致性
        """
        # ① 压缩率：验证集总 token 数 ÷ 总字符数（用没见过的文本考才真实）
        total_tokens = sum(len(self.tok.encode(t).ids) for t in val_texts)
        total_chars = sum(len(t) for t in val_texts)
        ratio = total_tokens / max(total_chars, 1)

        # ② 特殊标记：必须各自被编码成"一个" id，被拆碎即格式崩坏
        special_ok = all(len(self.tok.encode(t).ids) == 1 for t in SPECIAL_TOKENS)

        # ③ 往返一致：编码成 id 再解码回来，必须与原文一字不差
        # 注意 decode 默认会跳过特殊标记，必须显式关掉，否则模板标记"被解码丢了"
        sample = "<|user|>你是谁？<|assistant|>我叫小智~<|end|>"
        back = self.tok.decode(self.tok.encode(sample).ids, skip_special_tokens=False)
        roundtrip_ok = back == sample

        return {
            "ratio": ratio,
            "special_ok": special_ok,
            "roundtrip_ok": roundtrip_ok,
            "vocab_real": self.tok.get_vocab_size(),
        }


class TokenizerPipeline:
    """职责：只负责编排——供料 → 训练 → 保存 → 体检 → 给结论"""

    def run(self):
        # ① 供料：训练集练分词器，验证集当体检考场
        train_texts = CorpusExtractor(TRAIN_FILE).all_texts()
        val_texts = CorpusExtractor(VAL_FILE).all_texts()
        print(f"[read] 训练语料 {len(train_texts)} 条，体检语料 {len(val_texts)} 条")

        # ② 训练 + 保存
        tokenizer, out_path = BpeTrainer().train(train_texts)
        print(f"[train] 分词器已保存 → {out_path}")

        # ③ 保存后重新加载一次，验证文件本身可用（防止"存了个坏的"）
        reloaded = Tokenizer.from_file(str(out_path))

        # ④ 三道体检
        report = CompressionChecker(reloaded).check(val_texts)
        print(f"[check] 实际词表大小：{report['vocab_real']}（目标 {VOCAB_SIZE}）")
        print(f"[check] 压缩率：{report['ratio']:.2f} token/字"
              f"（健康区间 {GOOD_RATIO_MIN}~{GOOD_RATIO_MAX}）")
        print(f"[check] 特殊标记独占一格：{'✓' if report['special_ok'] else '✗'}")
        print(f"[check] 编解码往返一致：{'✓' if report['roundtrip_ok'] else '✗'}")

        # ⑤ 给结论：三关全过才放行
        ratio_ok = GOOD_RATIO_MIN <= report["ratio"] <= GOOD_RATIO_MAX
        if ratio_ok and report["special_ok"] and report["roundtrip_ok"]:
            print("[done] 体检全部通过！分词器可交付训练阶段使用")
        else:
            print("[warn] 体检未全过：压缩率不达标请调整 VOCAB_SIZE 后重跑")


if __name__ == "__main__":
    TokenizerPipeline().run()
04

验收 · 看懂体检报告

作用：一个文件、三个勾，齐了才往下走

验收就两行重点：实际词表大小是否达到目标（没练满说明语料还少，不致命但要记着），以及三个体检勾是否全亮。

哪个勾最不能妥协？特殊标记。压缩率差一点只是效率问题，特殊标记被拆碎是功能问题——模型的"谁在说、到哪停"全靠它们完整。脚本已把这条设为硬门槛。

交付物只有 tokenizer/tokenizer.json 一个文件。下一站把它交给模型训练脚本：加载它、把 train.jsonl 编码成 token 流、开训——见《v2 简单对话模型训练规划》第 04~05 阶段。

常见问题 · 一查就好

分词器阶段的问题都围绕"词表"和"语料"

现象 原因与处理
找不到 train.jsonl 上一步没跑或不在同目录 → 先运行 clean_split.py 生成 train/val
实际词表远小于 8192 语料太少，字都认不全 → 几百条数据时正常；等蒸馏数据涨到几千条以上重跑即可
压缩率高于 1.5 词表相对语料偏小 → 把 VOCAB_SIZE 调到 12288 或 16000 重练（注意嵌入层参数同步变大）
特殊标记被拆成多个 id 几乎只可能是标记名写岔了 → 核对 SPECIAL_TOKENS 与 clean_split.py 里的模板常量逐字符一致
往返不一致 / 编码后内容变少 两个高发根因：① 训练器漏了 initial_alphabet=pre_tokenizers.ByteLevel.alphabet()，语料没出现过的字节被静默丢弃；② 体检时 decode 没加 skip_special_tokens=False，特殊标记被默认跳过
pip install tokenizers 失败 网络问题 → 换国内镜像：pip install tokenizers -i https://pypi.tuna.tsinghua.edu.cn/simple
